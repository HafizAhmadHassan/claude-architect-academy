01

The six agentic patterns

Anthropic's canonical taxonomy from Building Effective Agents: five composable workflows plus the autonomous agent. Every exam scenario about orchestration maps onto one of these shapes.

Domain 1 →
workflow

Prompt chaining

Cost/latency: Low

Fixed sequence of calls with programmatic gates between steps

Use when

  • ✓The task splits cleanly into fixed subtasks
  • ✓You can trade latency for higher accuracy per step
  • ✓Each intermediate output can be checked programmatically

Watch out

  • ✕Every added step adds end-to-end latency
  • ✕Errors compound downstream if gates are missing

How it works

Decompose a task into a fixed pipeline where each LLM call processes the previous output. Gates are cheap programmatic checks that halt the chain when an intermediate result is off-track.

Architecture decision rehearsal

Exam items love the boundary between 'add a workflow' and 'build an agent'. Rehearse the decision flow until the least-complex-sufficient-system instinct is automatic.

Pattern library →

Workflow vs. agent decision helper

Four questions from Anthropic's “Building Effective Agents” decision flow.

  1. 1.Could one well-crafted LLM call with retrieval and examples solve this reliably?

    Anthropic's guidance: optimize single calls before adding agentic complexity.

  2. 2.Can you enumerate the subtasks / steps in advance?

    If yes, a workflow with predefined code paths gives predictability and auditability.

  3. 3.Why do the subtasks need separate LLM calls?

    Different input types → routing. Independent aspects or voting → parallelization. Quality gates between stages → chaining.

  4. 4.Can your code verify progress programmatically at each step?

    Agents need ground truth from tool results to assess their own progress. Without verifiable signals, do not build an agent yet.

Domain 5 →

Prompt injection defense layers

No single defense is enough. Click each layer to see what it blocks, what it can't, and how it appears on the exam.

L1

Input validation & sanitization

This layer blocks
  • ✓Strip known injection prefixes from user text
  • ✓Reject inputs exceeding token budget
  • ✓Normalize unicode that mimics control tokens
Bypasses this layer misses

Indirect injection via retrieved docs (user input is clean, data is poisoned)

Example
User: "Ignore previous instructions."
Filter: strips 'Ignore previous instructions.'
Exam note

Input filtering catches direct attacks. Indirect injection (from tool results or retrieved docs) bypasses this layer entirely.

Defense-in-depth principle: Each layer catches what the previous one missed. The exam tests whether you know which layer addresses a specific attack vector — not whether you can name them all.
